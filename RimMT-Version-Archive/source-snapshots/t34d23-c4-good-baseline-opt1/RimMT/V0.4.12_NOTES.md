# RimMT V0.4.12 Playtest — Stutter First

## Policy change

V0.4.12 explicitly prioritizes visible stutter / frame-time spikes over average TPS.

The V0.4.11 runtime test was thread-safe and reduced the observed JobGiver maximum from about 964 ms to about 790 ms, but the measured average JobGiver time did not improve and the GenClosest assist itself produced an approximately 15 ms outlier. User playtest feedback also reported more noticeable stutter than V0.4.10.1.

V0.4.12 therefore removes sources of foreground variance before attempting any broader search-space reduction.

## GenClosest changes

- Low pressure: no RimMT candidate reordering at all.
- Normal pressure: only IList-backed candidate sets with at least 512 entries are considered.
- High pressure: threshold 256.
- Critical pressure: threshold 192.
- Unknown `IEnumerable<Thing>` / non-IList inputs are never materialized by this feature.
- Removed the V0.4.11 foreground worker assist and all `SpinWait` / micro-wait behavior.
- Removed per-call X/Z snapshot arrays and worker-output arrays.
- Reuses thread-local integer scratch buffers for ring keys and offsets.
- Candidate membership remains exactly unchanged.
- A 0.75 ms hard assist budget aborts the current reorder before commit if RimMT itself becomes expensive.
- Any assist taking >=1.0 ms trips a 2-second cooldown during which this feature remains passive.
- Reentrant calls are bypassed to protect scratch-buffer integrity.

## Authority and safety

Unchanged:

- Vanilla `Reachability.CanReach` is authoritative.
- WorkGiver validators are authoritative.
- Reservations stay on the main thread.
- Final Job selection stays on the main thread.
- `parallel.pawnTick`, `parallel.reservations`, and `parallel.thingTick` remain disabled.
- PathSnapshot remains shadow validation only.
- All compatibility paths stay fail-closed.

## New telemetry to watch

`Adaptive GenClosest stutter guard V0.4.12` reports:

- `lowPressureBypass`
- `nonListBypass`
- `thresholdBypass(N/H/C)`
- `budgetAbort`
- `slowTrip`
- `cooldownBypass`
- `reentrantBypass`
- `scratchGrowths`
- `avgAssistUs` / `maxAssistUs`

Primary playtest success criteria:

1. Subjective stutter should be no worse than V0.4.10.1.
2. `maxAssistUs` should stay tightly bounded and should not approach the ~15 ms V0.4.11 outlier.
3. JobGiver maximum / >=64 ms slow-package frequency should fall without increasing frame-time variance.
4. Worker / dispatcher failures must remain zero.

TPS improvement is secondary for this build.
