# RimMT V0.4.16.3 — Full Reachability Harmony census

## Why this build exists

The V0.4.16 aggressive Reachability profile has been uncovering foreign Harmony patches one blocker at a time because the compatibility guard intentionally stops at the first unsafe owner. With a large mod list this creates an unnecessary iteration loop.

V0.4.16.3 adds a diagnostics-only runtime census of the exact RimWorld 1.5 overload:

`Reachability.CanReach(IntVec3, LocalTargetInfo, PathEndMode, TraverseParms)`

After the game reaches `ProgramState.Playing`, RimMT enumerates the complete Harmony patch chain in one pass and logs every:

- Prefix
- Postfix
- Transpiler
- Finalizer

For each patch it prints:

- Harmony owner
- priority
- exact declaring type + patch method
- before/after ordering constraints

This census does not change `__result`, does not replace Vanilla logic and does not mutate game state.

## Retained coexistence rules

- VFE / VFECore Phasing Prefix: exact whitelist, earlier authority retained.
- Pathfinding Framework v0.5.x debug Reachability Postfix: exact whitelist, diagnostics only.
- Hospitality guest-area Reachability Postfix: exact whitelist; it remains downstream authority and may tighten `true` to `false` for arrived guests outside `GuestArea`.
- Any other foreign Reachability patch remains blocking until audited.

## What to send back

After loading the high-load save once, search the log for:

`[RimMT] Reachability patch census BEGIN`

through:

`[RimMT] Reachability patch census END`

That block is sufficient to audit all remaining `CanReach` compatibility owners in one pass, instead of discovering them one build at a time.
