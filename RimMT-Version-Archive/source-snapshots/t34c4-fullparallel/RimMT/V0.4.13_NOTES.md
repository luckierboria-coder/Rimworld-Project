# RimMT V0.4.13 Playtest — True Offload

## Why this version exists

V0.4.12 reduced foreground assist work but the target 388-mod colony still showed frequent visible stutter. Runtime telemetry showed that JobGiver remained the dominant hot path while the eight RimMT workers were often idle. The design goal is therefore changed from "assist a search when it happens" to "precompute reusable search structure on spare cores before the next search needs it".

## New production path: worker-built custom GenClosest index

For the exact `ClosestThingReachable` shape where `ThingRequest` is undefined and a custom global list is actually used, RimMT can now cache repeated IList-backed sources.

- Supported source shapes: `IList<Thing>`, `IList<Pawn>`, `IList<Building>`.
- Minimum source size: 96 candidates.
- Exact `ListerHaulables` lists bypass this module and keep using the dedicated hauling accelerators.
- On cache miss the main thread snapshots only object references plus integer X/Z positions.
- Index construction runs on RimMT worker threads with `JobPriority.Normal`, so it is not starved merely because main-thread pressure is elevated.
- The triggering request never waits for the worker and falls back to Vanilla.
- At most four generic index builds may be in flight.

## Exact fail-closed validation

Before an accelerated call uses a published index, the entire source IList is checked against the snapshot:

- same count;
- same Thing reference at each source index;
- same X/Z position;
- same map identity and map dimensions.

Any mismatch invalidates the cache. That call uses Vanilla and schedules a rebuild. No stale index is allowed to change the result.

## Main-thread authority retained

The worker only builds immutable bucket/index data. It does not call Verse APIs or mutate live game objects. Accelerated queries still perform on the main thread:

- `Reachability.CanReach`;
- caller/WorkGiver validator;
- tie-breaking compatible with Vanilla source-list order;
- final Thing result;
- Job creation, reservation and Job start.

## What to measure

The V0.4.13 runtime report adds:

- cache hits / misses / invalidations;
- builds scheduled / published / discarded / rejected;
- active build count and build-busy bypasses;
- snapshot capture count/candidates/average microseconds;
- snapshot validation passes/failures/average microseconds;
- accelerated query average/max microseconds;
- candidate visits / candidates avoided;
- Reachability / validator checks;
- failures.

Primary acceptance criteria:

1. visible stutter lower than V0.4.12;
2. JobGiver P95/max lower;
3. worker utilization rises without worker/dispatcher failures;
4. no new Job/Reservation/path semantic errors;
5. TPS is evaluated only after smoothness is acceptable.
