# RimMT V0.4.14 — Persistent Map Search Fabric

## Purpose

V0.4.13 proved that true worker offload is stable in the target RimWorld 1.5.4063 environment, but its per-IList position snapshots were a performance regression: source movement invalidated caches and accelerated no-result searches still performed hundreds of live Reachability/validator calls.

V0.4.14 keeps the true-offload architecture and replaces disposable per-list position indexes with a persistent per-map worker-maintained search fabric.

## Changes

- Source caches retain only exact membership and original source-list order.
- Tracked positions are maintained incrementally from `ThingGrid.RegisterInCell` / `DeregisterInCell` events.
- Normal-priority RimMT workers consume immutable event payloads and publish immutable 12x12 spatial bucket views.
- The main thread never waits for a fabric build/update.
- Worker-side Thing keys use strict reference identity (`RuntimeHelpers.GetHashCode` + `ReferenceEquals`) rather than virtual Thing equality/hash behavior.
- Equal-distance results preserve Vanilla source-list tie ordering.
- Generic mobile Pawn-backed and unspawned/inventory-backed source sets are deliberately excluded and fall back to Vanilla.

## Stutter-first guard

V0.4.13 measured ~35 ms average and ~72.5 ms maximum RimMT query cost because broad no-result searches still checked ~440 live candidates.

V0.4.14 therefore refuses an accelerated query when the existing fabric predicts more than 64 structurally relevant candidates. The call returns directly to Vanilla before RimMT executes any live `Reachability.CanReach` or WorkGiver validator. Accepted calls are bounded to at most 64 live candidate checks.

This is intentionally conservative. The goal of this playtest is to prove that persistent true offload can remain active without becoming a source of visible stutter. Region/reachability topology offload is the next stage only after this baseline is non-regressive.

## Authority and safety

Workers never call live Reachability, validators, reservations or Job APIs. Final live candidate validation, `Reachability.CanReach`, WorkGiver validator execution, reservations and final Job selection remain main-thread/Vanilla authoritative. Stale, incomplete, unsupported or publication-lagged snapshots fall back immediately.

## What to compare

Primary metrics:

- visible stutter versus V0.4.12 and V0.4.13;
- `JobGiver_Work.TryIssueJobPackage` P95/max;
- `TickManager.TickManagerUpdate[ButterSlice]` P95/max;
- `Persistent-fabric GenClosest V0.4.14` `avgQueryUs` / `maxQueryUs`;
- `broadQueryBypass`, `candidatesVisited`, `candidatesAvoided`;
- map-fabric `workerEvents`, `published`, `snapshotHits`, `staleGenerationBypass`;
- scheduler/worker/fabric failures must remain zero.

V0.4.14 is successful only if it removes V0.4.13's self-inflicted query stalls while keeping real worker-side precomputation active.
