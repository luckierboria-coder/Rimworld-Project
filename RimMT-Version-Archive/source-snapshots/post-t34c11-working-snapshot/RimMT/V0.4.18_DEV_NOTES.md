# RimMT V0.4.18 Development Playtest

## Why this build exists

The V0.4.17.2 15-minute runtime trace showed that RimMT is already doing real worker-side work (24,950/24,950 worker jobs completed with zero failures), but it also exposed two remaining stutter sources:

1. `JobGiver_Work -> GenClosest -> Reachability/RegionTraverser` can still produce 100-200+ ms work-search stalls, with an observed JobGiver maximum above 1.3 seconds.
2. Path worker parity is promising for found/legal/endpoint results, but only 37 paired path samples were collected and exact path geometry is not yet reliable enough for authoritative use.

V0.4.18 therefore starts the next phase: attack broad GenClosest spikes while building the evidence needed for a future safe-authoritative Path mode.

## Changes in this development build

### ReachProfile positive-authority safety guard

V0.4.17.2 sampled 162,378 reachability predictions and found eight mismatches. All eight were `predicted reachable / Vanilla false`; there were no `predicted unreachable / Vanilla true` mismatches in that run.

V0.4.18 therefore changes effective policy:

- Profile `Unreachable` may remain a hard-negative fast result.
- Profile `Reachable` must be confirmed by live Vanilla `CanReach` before it can affect gameplay.
- The exact `ReachabilityImmediate` cheap-true shortcut is preserved.
- Existing profile cooldown/fuse logic remains active.

This deliberately trades some average Reachability speed for stronger correctness while the model is improved.

### Broad GenClosest nearest-first ordering

The V0.4.14 persistent-fabric consumer intentionally bypasses queries predicted to require more than 64 live checks. Runtime profiling showed that these broad queries are precisely where the large JobGiver spikes remain.

V0.4.18 adds a second, conservative layer for supported broad custom-global searches:

- Candidate membership is unchanged.
- Candidate order is changed to exact squared-distance nearest-first.
- Equal-distance candidates retain original source order.
- Vanilla still performs every validator, live Reachability check, reservation-sensitive decision and final selection.
- No worker is synchronously waited on.
- Exact `ListerHaulables` searches stay on the existing hauling path.
- Pawn/mobile candidate lists are not reordered by this layer.

The goal is to let Vanilla establish a tight nearest valid distance earlier, reducing expensive checks on farther candidates without replacing Vanilla selection semantics.

### Expanded Path shadow parity campaign

Path shadow remains 100% non-authoritative in this build.

Sampling is expanded from the previous 64-result budget to 512 paired validations:

- Low load: sample every 2nd eligible request, max validation distance 128 cells, up to 2 shadow requests in flight.
- Normal load: sample every 4th eligible request, max validation distance 96 cells, max 1 in flight.
- High/Critical load: no shadow admission.

This is intended to produce hundreds of real path pairs in a normal play session so the next SafePathClass can be designed from evidence rather than a 37-sample set.

## What to inspect after playtesting

Generate a RimMT runtime report after roughly 10-20 minutes of normal colony play. The most useful fields are:

- `Broad GenClosest ordering V0.4.18`: reordered calls, candidate counts, average/max sort time, failures.
- `JobGiver_Work.TryIssueJobPackage`: average, P95 and maximum time.
- Slow JobGiver detail traces: especially `GenClosest.ClosestThingReachable`, `GenClosest.ClosestThing_Global`, `Reachability.CanReach`, and `RegionTraverser.BreadthFirstTraverse`.
- `Reach-profile V0.4.18 positive guard`: how many positive profile results were forced back through Vanilla.
- `Aggressive reachability profile`: new parity mismatch direction/count.
- `Path shadow budget V0.4.18`: number of low/normal eligible samples and pressure/concurrency skips.
- `Path snapshot worker`: found/legal/endpoint parity, exact geometry, cost within 1%/5%, average/max cost delta, and worker failures.
- Worker queue: rejected/failures should remain zero in normal play.

## Not enabled yet

This build does **not** make worker path results authoritative. Path worker output remains shadow-only. A later build may introduce a narrow SafePathClass only after a substantially larger parity dataset shows that the selected request class is safe.
