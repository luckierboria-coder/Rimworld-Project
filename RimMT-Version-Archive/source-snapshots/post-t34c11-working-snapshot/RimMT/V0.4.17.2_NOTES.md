# RimMT V0.4.17.2 Playtest Notes

## Why this hotfix exists

The V0.4.17.1 loaded-save report on the target ~390-mod environment produced:

- GrowerSow = false
- GrowerHarvest = true
- BuildRoof = false

GrowerSow was still blocked by the exact ReGrowth Core patch:

`Helixien.ReGrowthCore :: ReGrowthCore.PlantExpandable+WorkGiver_GrowerSow_JobOnCell_Patch.Prefix`

Source review of ReGrowth 1.5 shows that this Prefix/Postfix bracket a shared `isJobSearchingNow` flag. ReGrowth's `PlantUtility.GrowthSeasonNow` Prefix uses that context for custom `PlantExtension` temperature limits and, outside the bracket, may read `PlantExpandable.allPlants`, a normal Dictionary maintained by Spawn/DeSpawn.

## V0.4.17.2 policy

Exact source-reviewed Biomes Core and ReGrowth Core GrowerSow boundary patches may coexist only in restricted season mode.

In restricted mode RimMT worker-side Sow classification does **not call `PlantUtility.GrowthSeasonNow`**. The worker may still publish only these hard negatives:

- no desired plant
- the desired plant is already present

All growth-season decisions remain live Vanilla main-thread authority, including Biomes/ReGrowth semantics.

Humanoid Alien Races GrowerHarvest exact downstream restriction coexistence from V0.4.17.1 is retained.

Watchtowers BuildRoof remains fail-closed.

## Expected compatibility log

After entering `ProgramState.Playing`, the V0.4.17 core may first print its conservative false/false/false result. The compatibility layers run afterward.

Expected final effective state on the current target mod list:

`kindCompat(sow/harvest/roof)=True/True/False`

Expected V0.4.17.2 lines include:

- `enables GrowerSow prefilter in restricted season mode`
- `exactBiomes=True`
- `exactReGrowth=True`
- Harvest re-enabled by the V0.4.17.1 AlienRace exact coexistence layer

## Runtime acceptance

Do not call Work-prefilter performance successful from the startup frame alone. Let the loaded save run under normal work activity and then inspect a runtime report.

Required evidence:

- `sourceEnumerations > 0`
- `sourceCellsCaptured > 0`
- `buildsScheduled > 0`
- `buildsPublished > 0`
- `workerCells > 0`
- `negativeHits > 0`
- `authoritativeFalse > 0` after warmup
- `workerReadFaults = 0` ideally
- sampled `parityMismatches = 0` ideally
- no missed sow/harvest jobs or new red errors

Compare JobGiver P95/max and slow traces against the previous V0.4.16/0.4.17 baselines only after real worker workload is present.
