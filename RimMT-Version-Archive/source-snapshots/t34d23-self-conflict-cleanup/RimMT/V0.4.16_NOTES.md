# RimMT V0.4.16 — Aggressive Parallel Reachability

## Why this build exists

V0.4.15 proved that RimMT's scheduler can genuinely fan out across all eight configured workers (`peakActive=8/8`) on a 12-logical-processor machine. Its first permissive whole-map Region hint was stable, but real runtime telemetry showed `accelerated=0`: nearly every supported query either missed a fresh snapshot or stayed inside the same broad component.

V0.4.16 therefore increases the risk budget in a controlled way. The goal is no longer only to prove that a candidate is definitely disconnected. It builds per-Pawn traversal profiles close to Vanilla's actual Region rules and allows validated predictions to answer selected `Reachability.CanReach` calls without entering live `RegionTraverser`.

## New: per-Pawn Reachability profiles

- Exact live `Region.Allows(TraverseParms, false/true)` decisions are captured on the main thread.
- Region cell membership, district membership and Region links are copied into RimMT-owned arrays.
- Worker threads dereference no Verse `Region`, `Pawn`, `Map`, `Thing` or `Door` objects while building connectivity.
- Workers label connected components for the captured Pawn/TraverseParms shape.
- Supported initial traversal modes: `ByPawn`, `PassDoors`, `NoPassClosedDoors`.
- Supported initial path-end modes: `OnCell`, `Touch`, `ClosestTouch`.
- Vanilla's cheap immediate-reachability shortcut is preserved before profile use.

## Bounded-risk validation

Dynamic door state, danger and avoid grids can change between captures. To contain that risk:

1. Every fresh profile starts with 8 shadow samples that still run live Vanilla and compare the result.
2. After warm-up, one prediction in every 16 is sampled against Vanilla.
3. The first mismatch invalidates that profile and disables authoritative use for that profile for 600 main-thread frames.
4. 16 sampled mismatches globally suppress `parallel.reachProfile` for the rest of the session.
5. Unsupported shapes always fall back to Vanilla.
6. Jobs, reservations and all gameplay-state commits remain on the main thread.

## VFECore Phasing coexistence

Vanilla Expanded Framework patches `Reachability.CanReach` so phasing Pawns are always reachable. RimMT runs its prefix after that known VFECore prefix and respects `__runOriginal=false`; VFECore keeps authority for phasing results. Any other unknown foreign patch on this Reachability overload remains a compatibility blocker.

## Scheduler

The V0.4.15 semaphore work-credit fan-out remains unchanged. Worker count is still capped at 8 in this playtest. The objective is to increase useful parallel workload before considering a 9–10 worker pool on 12+ logical processors.

## Runtime metrics to inspect

`Aggressive reachability profile V0.4.16` reports:

- `profileHits / profileMisses / profileExpired`
- `buildsScheduled / buildsPublished / workerFailures`
- `predictedReachable / predictedUnreachable`
- `authoritativeTrue / authoritativeFalse`
- `shadowSamples / shadowMatches / parityMismatches`
- mismatch direction (`predTrue/liveFalse`, `predFalse/liveTrue`)
- topology/profile capture time and worker build time
- query time

The primary success criterion is a material reduction in live `Reachability.CanReach` / `RegionTraverser.BreadthFirstTraverse` cost inside slow JobGiver packages without parity mismatches or new job/pathing failures.
