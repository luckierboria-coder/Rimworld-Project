# RimMT V0.4.18.3.1 — ReachProfile Regression Rollback

## Why this build exists
The first V0.4.18.3 runtime sample in the 390-mod test save showed a severe performance regression rather than a deadlock. Worker and dispatcher queues remained healthy, but JobGiver and overall tick long-tail latency increased sharply.

Measured V0.4.18.3 sample:
- Worker queue: 2446 enqueued / 2446 completed / 0 failures.
- Dispatcher: 97 enqueued / 97 drained / 0 failures.
- DoSingleTick: 24.758 ms average, ~64 ms P95.
- JobGiver_Work: 49.976 ms average, 856.676 ms max.
- ReachProfile: 189,365 profile misses, pending high-water 517.
- Stable spatial GenClosest: 61% signature hit rate but 0 accelerated calls.

The frame-budgeted capture chunks themselves were cheap (max ~0.72 ms). The regression came from delayed profile availability: cold requests accumulated while captures were being completed over later frames, causing many calls to fall back to live Vanilla Reachability/RegionTraverser.

## V0.4.18.3.1 changes
- Restore the V0.4.18.2/V0.4.16 `AggressiveReachabilityProfiles` implementation.
- Restore synchronous main-thread profile capture followed by worker graph construction.
- Keep sampled positive/negative authority, warmup, parity sampling, per-profile cooldown and global mismatch fuse.
- Disable the V0.4.18.3 stable-spatial GenClosest consumer.
- Keep the V0.4.18.2 identity-keyed async candidate plan retired.
- Keep the V0.4.15 RegionHint/ParallelRegionConnectivity path retired.
- Keep Broad GenClosest ordering, JobGiver nearest-first ordering, WorkPrefilter, haul accelerators and path shadow telemetry unchanged.

## Test goal
This is a narrow regression-isolation build. Compare directly against the clean V0.4.18.2 baseline with Butter++ and Adaptive TPS disabled. The first success criterion is to return JobGiver average latency toward the prior ~11–20 ms range and materially reduce the ~64/128 ms long tails before any new architecture work resumes.
