# RimMT V0.4.18.3 — AI Stutter Reduction

## Baseline used

The primary comparison baseline is RimMT + Performance Fish with Butter++ and Adaptive TPS disabled. In the measured save this produced roughly 20 ms average DoSingleTick, ~32 ms P95, ~11.65 ms average JobGiver_Work and ~346 ms JobGiver max. Remaining slow Job packages are dominated by GenClosest -> Reachability -> RegionTraverser.

## ReachProfile lifecycle rewrite

- Region generation is now the primary profile validity key.
- 900 main-thread frames is a soft refresh interval, not an expiry. A validated profile continues serving queries while its replacement is captured and built.
- 3600 frames is a defensive hard-age fuse for dynamic traversal state that may not emit a RegionDirtyer signal.
- Existing sampled warmup/parity, per-profile mismatch cooldown and global mismatch fuse are preserved.
- RegionDirtyer walkability/spawn/despawn/all-dirty signals still invalidate the generation immediately.

## Budgeted Region.Allows capture

V0.4.16 captured every Region.Allows result synchronously inside the requesting CanReach call. V0.4.18.3 replaces that with a main-thread capture queue pumped at TickManagerUpdate boundaries.

- target capture budget: 0.80 ms per frame
- at most 64 regions per capture chunk
- topology/pawn ownership is revalidated between chunks
- stale partial captures are discarded rather than published
- only completed primitive allow arrays are sent to workers
- workers still never dereference Region/Pawn/Map/Thing state

New telemetry includes captureStarts, captureChunks, captureCompleted, topology/pawn-state discards, pending high-water, budget yields, average/max chunk time, average regions per chunk and retained profile hits during refresh.

## Stable spatial GenClosest reuse

V0.4.18.2's AsyncJobCandidatePlan keyed reuse by exact IList identity and exact query root, which produced negligible hits with JobGiver's temporary lists. V0.4.18.3 replaces that active path with `StableGenClosestAssist04183` on top of the existing `PersistentMapSearchFabric`.

- supported source membership is fingerprinted by ordered Thing reference identity
- a fingerprint is only a lookup accelerator; every retained member is compared with `ReferenceEquals` before sourceId reuse
- identical temporary lists can therefore reuse the same worker-maintained spatial source even when the IList object is new
- positions remain worker-maintained through the existing ThingGrid event fabric
- candidate count is estimated from spatial buckets before any live Reachability or validator call
- queries estimated above 128 live candidates immediately fall through to Vanilla without speculative live checks
- supported sources that are new register asynchronously and keep the current cold request Vanilla-authoritative

New telemetry reports signature lookups/hits/hit rate, collisions, source creates, fabric misses, broad-query bypasses, capture cost, candidates visited/avoided and live Reachability/validator counts.

## Retired low-yield paths

- V0.4.18.2 `AsyncJobCandidatePlan04182` is no longer installed.
- V0.4.15 `ParallelRegionConnectivity` is no longer installed. It repeatedly built/staled permissive connectivity snapshots while producing zero measured accelerations in the target workload.

## Safety boundaries unchanged

- final WorkGiver predicates: main thread
- reservations: main thread
- Job creation/commit: main thread
- mutable Verse/Unity state: main thread
- path worker: shadow-only
- spatial signatures never replace reference-by-reference membership validation
