# RimMT V0.4.16.1 — Pathfinding Framework Reachability compatibility hotfix

## Why this hotfix exists

The first V0.4.16 runtime test on the user's full RimWorld 1.5.4063 mod list proved the DLL and scheduler loaded correctly, but `parallel.reachProfile` never became eligible. The compatibility report showed it was disabled because `pathfinding.framework` owns a Postfix on `Verse.Reachability.CanReach`.

Source review of Pathfinding Framework v0.5.x confirmed that exact Postfix is diagnostics-only:

`PathfindingFramework.Patches.DevTool.PathDebugging.Reachability_CanReach_DebugPatch.Postfix`

It receives `bool __result` by value and only calls `LastReachabilityResult.Store(...)` for later error reporting. It does not alter the reachability result.

## Exact coexistence rule

V0.4.16.1 allows only this exact combination:

- feature: `parallel.reachProfile`
- target: `Verse.Reachability.CanReach(IntVec3, LocalTargetInfo, PathEndMode, TraverseParms)`
- Harmony owner: `pathfinding.framework`
- patch kind: `postfix`
- declaring type: `PathfindingFramework.Patches.DevTool.PathDebugging.Reachability_CanReach_DebugPatch`
- method: `Postfix`

Any other Pathfinding Framework patch on `Reachability.CanReach`, and every unknown foreign Reachability patch, remains a compatibility blocker.

## Pathfinding Framework movement semantics remain authoritative

Pathfinding Framework also transpiles `Region.Allows` to apply custom movement types and terrain passability. RimMT does not bypass or whitelist that logic. The V0.4.16 profile builder calls the live patched `Region.Allows(traverseParms, isDestination)` on the main thread and copies only the resulting permission arrays to workers. Therefore PF movement-type decisions are included in each captured profile.

PF's `Region.Allows` logic also depends on dynamic Pawn state such as the Pawn's current terrain. This remains within the V0.4.16 bounded-risk model:

- every fresh profile starts with 8 live Vanilla/PF shadow comparisons;
- after warm-up, one prediction in every 16 is checked live;
- the first mismatch invalidates and cools down that profile for 600 main-thread frames;
- 16 sampled mismatches globally fuse `parallel.reachProfile` off for the session.

## What to verify in the next runtime log

The compatibility report should now show `parallel.reachProfile: ACTIVE` plus coexistence lines for VFE Phasing and the Pathfinding Framework diagnostics Postfix.

Then inspect:

- `eligible > 0`
- `buildsScheduled / buildsPublished > 0`
- `profileHits > 0`
- `shadowSamples / shadowMatches > 0`
- later `authoritativeTrue + authoritativeFalse > 0`
- `parityMismatches`, especially `predFalse/liveTrue`
- JobGiver / Reachability / RegionTraverser P95 and max values

No changes were made to the V0.4.16 reachability algorithm itself in this hotfix.
