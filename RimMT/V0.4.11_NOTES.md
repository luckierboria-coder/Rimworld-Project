# RimMT V0.4.11 — Job Search Spike Reduction

## Why this version exists

A 30-minute V0.4.10.1 run showed that `PathFinder.FindPath` is no longer the dominant hot path in this save: about 34.8k path calls averaged roughly 0.21 ms, while `JobGiver_Work.TryIssueJobPackage` averaged roughly 17.8 ms and reached a ~964 ms maximum. Bounded JobGiver detail capture repeatedly placed `GenClosest.ClosestThingReachable`, `GenClosest.ClosestThing_Global`, `Reachability.CanReach`, and `RegionTraverser.BreadthFirstTraverse` at the top of slow packages.

V0.4.11 therefore focuses on reducing search spikes without moving gameplay authority off the main thread.

## Changes

- Replaces V0.4.10's fixed single-call partition activation policy with **pressure-adaptive GenClosest assistance**.
- Candidate threshold adapts conservatively to measured load pressure:
  - Low: 128
  - Normal: 96
  - High: 80
  - Critical: 64
- Spatial ring granularity also adapts with pressure so a closer candidate can be established earlier during stressed frames.
- Exact candidate membership is preserved. RimMT only changes supported custom-global candidate order.
- `Reachability.CanReach`, WorkGiver validators, reservations, and final Job selection remain on the main thread and remain authoritative.
- Exact ListerHaulables paths continue to bypass this feature and use the established V0.4.6/V0.4.7 hauling accelerators.

## Important worker-assist safety change

V0.4.10 had a nominal 0.20 ms worker budget, but a missed budget eventually waited for the worker anyway. V0.4.11 removes that hidden stall.

The new worker assist:

1. only receives immutable primitive position snapshots;
2. runs only for substantially larger candidate sets;
3. permits at most one assist to outlive its budget;
4. uses a tiny pressure-dependent micro-budget;
5. **never waits for a late worker**;
6. immediately performs the cheap main-thread integer fallback if the deadline is missed;
7. discards late worker output.

This keeps the worker opportunistic instead of making the main thread dependent on it.

## New diagnostics

The runtime report now includes:

- current pressure / current candidate threshold / current ring size;
- calls observed under Low/Normal/High/Critical pressure;
- worker attempts, in-budget completions, deadline misses, late completions, rejections, and busy bypasses;
- main-thread key-build fallback count;
- average and maximum assist overhead in microseconds;
- candidate counts and failures.

## Intentionally unchanged

- `parallel.pawnTick` remains OFF.
- `parallel.reservations` remains OFF.
- `parallel.thingTick` remains OFF.
- Worker path snapshots remain shadow validation only; Vanilla/Clean Pathfinding remain authoritative.
- Unsupported or ambiguous GenClosest call shapes fall back to Vanilla.

## Playtest targets

Compare a 20–30 minute V0.4.11 run against V0.4.10.1 using:

- `JobGiver_Work.TryIssueJobPackage` average / max / slow-package count;
- `GenClosest` / `RegionTraverser` / `Reachability` inclusive timings;
- `Adaptive GenClosest assist V0.4.11` pressure distribution and overhead;
- worker `failures`, dispatcher `failures`, and circuit-breaker state;
- gameplay correctness: no changed reservations, no duplicate Jobs, no missing reachable work.
