# RimMT V0.4.16.2 — Hospitality Reachability coexistence hotfix

## Runtime finding

The first V0.4.16.1 full-save test proved the Pathfinding Framework exact whitelist worked: the compatibility report showed RimMT coexisting with both VFE Phasing and `pathfinding.framework`. The next blocker was then exposed:

`parallel.reachProfile disabled: foreign Harmony postfix by 'Orion.Hospitality' on Verse.Reachability.CanReach`

Because the guard suppresses the feature before eligibility, the test still showed `eligible=0`, `profileHits=0`, `buildsPublished=0`; therefore V0.4.16/0.4.16.1 aggressive Reachability parity had still not actually been exercised.

## Hospitality source audit

Hospitality patches the exact RimWorld 1.5 overload:

`Reachability.CanReach(IntVec3, LocalTargetInfo, PathEndMode, TraverseParms)`

with:

`Hospitality.Patches.Reachability_Patch+CanReach.Postfix(ref bool __result, LocalTargetInfo dest, TraverseParms traverseParams)`

The Postfix is gameplay-authoritative, not diagnostics-only. It returns immediately when Vanilla/RimMT already says unreachable. For an arrived Hospitality guest with a configured `GuestArea`, it changes `true` to `false` when the destination is invalid or outside that area.

This is a monotonic restriction: it never changes `false` to `true`.

## Why exact coexistence is safe

Harmony Postfixes still run when an earlier Prefix skips the original and supplies `__result`. Therefore when a validated RimMT profile returns `true`, Hospitality still executes afterwards and can tighten the result to `false` for an out-of-area guest. RimMT cannot bypass the GuestArea restriction through this ordering.

If RimMT predicts `false`, Hospitality leaves it false; false-negative risk remains covered by the existing V0.4.16 shadow-validation/sampling policy.

V0.4.16.2 whitelists only:

- feature: `parallel.reachProfile`
- target: `Verse.Reachability.CanReach(IntVec3, LocalTargetInfo, PathEndMode, TraverseParms)`
- Harmony owner: `Orion.Hospitality`
- patch kind: `postfix`
- declaring type: `Hospitality.Patches.Reachability_Patch+CanReach`
- method: `Postfix`

No other Hospitality or foreign Reachability patch is allowed automatically.

## Retained safety policy

- VFE Phasing prefix keeps earlier authority.
- Pathfinding Framework diagnostics Postfix remains exact-whitelisted.
- Fresh profiles begin with 8 shadow-validation samples.
- After warmup, one prediction every 16 is checked against live Vanilla/modded Reachability.
- First mismatch invalidates and cools down that profile for 600 main-thread frames.
- 16 sampled mismatches globally fuse `parallel.reachProfile` off for the session.
- Worker threads do not commit Pawn jobs, reservations or gameplay-state mutations.
