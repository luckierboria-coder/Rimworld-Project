# RimOPT 0.1.3 S4/T34-B work-search port

This release puts the old RimMT S4 validator-first tail and T34-B source-indexed distance-plan idea in RimOPT, not RimMT 2.0. It does not install the 1.5 code or scheduler.

The 1.6 `GenClosest.ClosestThingReachable` source was checked against the local `Assembly-CSharp.dll`. This route admits only `JobGiver_Work`'s original validator, a custom `IList<Thing>` of 16-4096 live spawned Things, an undefined `ThingRequest` (so the 1.6 method does not run region search), the default unbounded region arguments, no haul-source expansion, and a Work package already over 16 ms. A foreign transpiler/finalizer on this exact method disables the route. Unsupported calls run the original method.

An admitted call sorts source positions by squared horizontal distance with original-list index as the tie key. The plan belongs to exactly one synchronous Work package. Reuse checks list identity, count, each Thing identity and each position; any change invalidates the plan. The live original validator and `CanReach` still decide the result. Unlike the 1.6 global fallback, this route calls the validator before `CanReach`, reducing wasted reachability for rejected candidates. No worker, cross-Pawn cache, Job result or reservation result is involved.

Local .NET 8.0.425 build against RimWorld 1.6.4871 completed with zero warnings and zero errors. This is structural evidence only. A fresh-session acceptance check must confirm `[RimOPT] 0.1.3 active`, nonzero `tailPlans admitted`, no module failures, normal Pawn work, and lower work-search tail latency/TPS variance on the same save compared with 0.1.2. Keep the 0.1.2 package for rollback if candidate order or WorkGiver behavior differs.
